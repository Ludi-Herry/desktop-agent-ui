# Agent 应用的交互结构与任务状态流

本章提炼了现代桌面 Agent 应用在人机协作、生命周期状态、工具执行与界面布局上的核心设计规范。

---

## 1. 任务形态决定界面布局

在开始设计之前，首先明确用户的核心任务与操作对象，再决定会话气泡、结构化表单、工作台面板与产物画布之间的空间拓扑：

- **目标澄清与探索**：适合通过流式对话推进，利用语言的灵活性迅速收敛模糊需求；
- **高频编辑与精确调参**：必须提供 GUI 结构化控件（滑块、分段器、表单），避免用户陷入来回打字的低效沟壑；
- **产物消费与协同修改**：当修改文档、代码或图形对象时，用户与 Agent 应共享同一份草稿与保存目标；在聊天气泡中给出的修改建议、预览视图中的临时渲染与最终落盘的对象必须具有清晰的视觉边界。
- **画布空间（Canvas）**：适用于多对象关联或空间编排任务；当画布元素作为对话上下文时，必须有明确的高亮选中提示，杜绝让用户猜测 Agent 到底读取了全局还是局部。

---

## 2. 用户对 Agent 的控制权可落实性（RICH 范式）

人机协作的核心在于维持用户的确定性信任。控制权必须体现在具体可操作的界面要素上：

| 委托原则 | 界面落地形态 | 核心核验标准 |
| --- | --- | --- |
| **可见（Visible）** | 当前任务标题、正在执行的步骤、受影响的目标文件 | 状态与后端真实事件严格绑定，无虚假演出动画 |
| **可解释（Explainable）**| 关键决策依据、引用来源摘要、当前操作的作用范围 | 披露关键上下文与参数，不强行暴露模型冗长自语 |
| **可介入（Interruptible）**| 编辑草稿、实时暂停、补充说明、修改后续执行队列 | 明确操作如何作用于正在运行或排队的任务 |
| **可收回（Revocable）** | 终止任务按钮、回滚快照入口、撤销（Undo）机制 | “发出停止请求”与“已安全停止”必须严格分状态展示 |
| **可追责（Accountable）** | 执行审计日志、Diff 差异比对、版本历史记录 | 用户可清晰追溯哪个工具在何时修改了哪个文件 |

> [!IMPORTANT]
> 授权确认机制应依据操作的影响范围与可逆性灵活设计。只读查询自动放行；涉及文件删除、外部发布或写操作时，清晰呈现受影响对象与影响范围，而不是对每一步琐碎动作都弹窗打扰用户。

## 3. 会话与任务的全生命周期状态流

每个交互状态都必须在界面上有清晰表达，并能明确回答以下问题：

| 交互状态 | 用户能看到什么 | 用户可进行的操作 | 异常时保留什么 |
| --- | --- | --- | --- |
| **草稿态（Drafting）** | 输入框、已附带的上下文 Chip、参数设置 | 自由打字、拖入文件、随时清除 | 切换会话或临时中断时草稿自动暂存 |
| **已受理/排队中（Queued）** | 任务已被系统接收的微弱指示、排队位次 | 允许即时撤回或取消排队 | 未开始执行前撤回无任何副作用 |
| **执行运行中（Running）** | 正在执行的子步骤标签、流式文字渲染、已完成步骤打勾 | 可随时点击「停止/中断」按钮 | 中断时保留已生成的部分输出与已确认产物 |
| **等待授权（Pending Approval）**| 工具调用卡片、拟执行命令、受影响参数高亮 | 允许、拒绝、提供补充指令 | 超时或拒绝后任务优雅暂停，不崩溃报错 |
| **已完成（Completed）** | 结构化最终结论、生成的产物卡片（Artifact） | 查看、一键复制、在外部打开、基于结果继续对话 | 完整记录沉淀在历史流中，可随时回溯 |
| **失败/停止（Failed/Aborted）** | 明确的错误根因、已中断的断点标记 | 一键安全重试、修改参数后重试 | 错误依据与已生成的阶段结果完整保留 |

## 4. 对话、过程、工具与产物的正交分层

现代桌面 Agent 界面严禁将所有内容挤压在一个冗长的单列气泡流中：

1. **主对话层（Conversation Layer）**：承载用户的原始意图表达与 Agent 的最终结论回复；
2. **思考与过程层（Reasoning & Process Layer）**：
   - 采用可折叠的时间轴（Reasoning Timeline）；
   - 在流式生成时展示简明的阶段标签（如“正在检索相关代码...”），生成完成后收拢为轻量摘要，不占用首屏主视线；
3. **工具执行卡（Tool Execution Card）**：
   - 将每一次工具调用的发起、参数输入、执行状态与返回结果封装在同一张独立卡片内；
   - 严禁每个事件零散打印一行系统文本；
4. **产物层（Artifacts / Workspace Layer）**：
   - 生成的大段代码、Markdown 报告、交互原型或设计稿独立开辟在右侧或专用工作台面板中；
   - 支持独立滚动、版本切换、本地保存与全屏放大。

## 5. 多会话与多线程桌面管理

在桌面端多任务场景下：
- **线程切换隔离**：当用户在侧边栏切换不同任务线程时，各线程的未发送草稿、附件上下文与运行中任务必须严格隔离并持久化，切勿因组件卸载导致输入内容丢失；
- **后台任务可观测**：在后台线程运行的任务，若进入等待授权或出错状态，在侧边栏对应条目上需有轻量状态红点或徽章提示；
- **连接恢复与幂等性**：断网或重开窗口后，优先拉取服务端权威快照恢复界面，禁止在前端无脑重放可能具有破坏性副作用的操作请求。
