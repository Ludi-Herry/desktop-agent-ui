# 架构与设计参考索引（Architecture & Reference Catalog）

本索引梳理了本 Skill 各项技术规范、避坑经验与工程方案的核心机制与适用边界，便于开发者快速定位对应设计模式。

---

## 核心机制与工程方案对照表

| 规范 ID | 核心工程领域 | 关键机制与设计方案 | 适用边界与约束 |
| --- | --- | --- | --- |
| **ENG-01** | 阴影与祖先裁切 | 外扩安全距离计算公式（`offset + blur + spread`）；内外分层（内层圆角、外层投影）；透明窗口物理尺寸同步 | 阴影所在容器必须与 `overflow: hidden` / `clip-path` 祖先保持足够边距，详见 [避坑指南](desktop-pitfalls.md) |
| **ENG-02** | 动效中间帧遮罩 | 文字升起动效使用与位移同步的渐变羽化遮罩（Gradient Mask）消除水平硬切线 | 仅适用于单向位移或渐隐出现场景，复杂三维形变需结合 SVG 遮罩 |
| **ENG-03** | `clip-path` 曲线 | `clip-path: inset(...)` 必须显式携带 `round` 参数继承宿主圆角曲率 | 自动化 DOM 矩形检测无法验证圆角像素，需人工肉眼或截图复核 |
| **ENG-04** | 滚动槽位抖动 | 根滚动容器配置 `scrollbar-gutter: stable` 保留槽位，防止弹窗打开时页面横跳 | 嵌套桌面面板需按实际滚动归属容器配置，避免多层重复预留 |
| **ENG-05** | 输入框自适应增高 | 三层机制：`field-sizing: content` / ResizeObserver、外层弹性高度过渡、外层 `overflow: visible` | 设定明确的 `max-height`，超出后转内部滚动，详见 [组件实现](components-motion.md) |
| **ENG-06** | 局部滚动条收敛 | 在自适应输入框等微交互区域，通过 `scrollbar-width: none` 局部消除粗糙的灰色系统滚动条外观 | **严禁全局禁用**；必须完整保留鼠标滚轮、触控手势与键盘滚动语义 |
| **ENG-07** | CJK 伴生键守卫 | 记录 `compositionend` 时间戳，对 500ms 内到达的伴生 Enter 进行拦截并**立即清空时间戳** | 确保中文拼音选词时不误发消息，同时不误吞后续正常的连续击键 |
| **ENG-08** | 分栏拖拽与取消闭环 | 边缘（≤18% 或 ≥82%）折叠吸附；按 `Escape` 取消拖拽时，状态机显式重置并保留 `previousRatioRef` | 防止拖拽中途取消导致分割手柄 DOM 被卸载而引发界面死锁 |
| **ENG-09** | 纯 CSS 滚动渐变遮罩 | Chromium 115+ 环境利用 CSS Houdini `@property` 与 `animation-timeline: scroll()` 在合成器线程驱动 | 达成 0.0% CPU 占用与 0ms 主线程阻塞（Zero-JS），替代传统频繁的 JS 测距 |
| **ENG-10** | Broker-Replica 多窗口 | 主窗口作为权威 Broker，独立弹出窗口作为 Replica 订阅不可变状态流；工作区基线乐观锁仲裁 | 防止多窗口并发写入或修改同一会话/文件时发生状态脏覆盖 |
| **ENG-11** | 视口智能跟随算法 | 基于 `distanceFromBottom` 动态判定：用户贴底时平滑跟随，用户向上翻阅时立即冻结自动滚动 | 防止模型高速流式吐字时强行将正在阅读历史消息的用户拽回底部 |
| **ENG-12** | RICH 任务控制权 | 可见（Visible）、可解释（Explainable）、可介入（Interruptible）、可收回（Revocable）、可追责（Accountable） | 明确授权影响范围；只读操作自动放行，破坏性操作显式呈现受影响对象 |
| **ENG-13** | 正交分层布局 | 主对话层、过程时间轴层、工具执行卡片层、独立产物工作台层（Artifacts）四层物理隔离 | 严禁将所有长代码、Diff、工具输出强行压在单一的纵向消息气泡流中 |
| **ENG-14** | 自动化裁切审计 | 自动化脚本 [`scripts/clip-audit.js`](../scripts/clip-audit.js)，深度遍历检测所有投影与裁切祖先并计算物理交集 | 交付硬性门禁为 `cut === 0`；注意范围盲点（需指定目标组件的父容器为 root） |

## 最佳实践与维护规约

1. **增量演化原则**：当在具体项目中探索出新的桌面避坑方案时，按“触发症状 → 根因机制 → 最小解法 → 验证标准”提炼为通用模式并增补入本索引；
2. **保持解耦与通用性**：本 Skill 沉淀的是通用交互物理学、CSS 标准规范与现代桌面架构模式，避免依赖特定私有路径或私有工具链；
3. **真实运行时检验**：任何动效与阴影修复，必须在对应桌面外壳（Electron / Tauri / 真实浏览器引擎）中以真实缩放比（DPI）与真实输入设备进行终验。
